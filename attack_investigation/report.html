Краткое резюме

На рабочей станции от имени plat\vpupkin был запущен launcher.bat из каталога Downloads. Через cmd.exe был запущен PowerShell с параметрами обхода Execution Policy и закодированной командой. После декодирования команда показывает загрузку содержимого по HTTP с 10.158.3.4:9000/download/powershell/ и передачу результата в iex для выполнения в памяти. Сетевые события подтверждают соединения PowerShell с этим узлом. Позднее в журнале PowerShell появились команды перечисления файлов и получения сведений о Advanced_Research_Report.docx.

Эта последовательность указывает на подозрительную загрузку и выполнение PowerShell-кода с последующим поиском данных. Успешная передача документа за пределы хоста не подтверждена: в выгрузке нет события с содержимым файла или доказательством его отправки. Фактический объём утечки необходимо проверять по прокси, межсетевому экрану, DLP и журналам сервера 10.158.3.4.

Точка входа не установлена. В журналах виден запуск launcher.bat из Downloads, но события, объясняющего появление этого файла на компьютере, нет. Поэтому нельзя достоверно утверждать, что проникновение произошло через фишинг, RDP или эксплуатацию уязвимости.

  • Запуск PowerShell из cmd.exe, запущенного из Downloads.
  • Совместное использование -enc, -ep bypass и скрытого/минимизированного окна.
  • Загрузка HTTP-содержимого и немедленная передача в iex.
  • Соединение PowerShell с нестандартным портом 9000.
  • Последующее перечисление файлов и получение сведений о документе.

Хэши системных файлов cmd.exe и powershell.exe не приводятся как вредоносные IoC: сами по себе они не подтверждают компрометацию.

Момент для реагирования

Самый ранний надёжный признак — Sysmon Process Create RecordID 210355013 в 13:14:42.760 UTC: PowerShell запущен с -enc, -ep bypass и командой загрузки содержимого с последующим выполнением через iex. Сочетание этих признаков существенно подозрительнее, чем отдельный запуск BAT-файла из Downloads.

На этом этапе следует остановить PowerShell-процесс и его дочерние процессы, изолировать хост для проверки и сохранить телеметрию. Реагирование после повторного соединения или перечисления документов оставляет атакующему больше времени. Блокировка только по факту запуска BAT-файла могла бы привести к ложному срабатыванию без дополнительного контекста.

Рекомендации SOC

Поиск на других хостах

  • Искать запуск PowerShell с -enc/-EncodedCommand вместе с -ExecutionPolicy Bypass или -ep bypass, особенно если родитель — cmd.exe.
  • Проверить соединения PowerShell с 10.158.3.4:9000, а также другие обращения к адресу в Proxy, Firewall, DNS, NDR и EDR.
  • Искать команды Get-ChildItem и Get-Item, обращающиеся к Documents, Work\Reports, Salary_Calculation, Competitive_Analysis и файлам с префиксом IPO_.
  • Проверить Prefetch, Amcache, $MFT/USN Journal, Zone.Identifier, историю загрузок браузера, PowerShell Operational, Sysmon Operational, Security, Defender/EDR и сетевые журналы.

Сдерживание и устранение

  • Изолировать VPupkin.domain.com, сохранив канал EDR для расследования.
  • После проверки принадлежности адреса заблокировать 10.158.3.4:9000 и проверить остальные подключения к нему.
  • Проверить активные сессии и токены plat\vpupkin; при подтверждении компрометации отозвать их и сменить пароль с чистого устройства.
  • Сохранить launcher.bat, его хэш, журналы и сетевые артефакты. Проверить Run/RunOnce, Scheduled Tasks, Services, WMI subscriptions, Startup, PowerShell profiles и новые учётные записи.
  • Проверить DLP, Proxy, Firewall и серверные журналы, чтобы установить, передавался ли документ. Отдельно проверить остальные целевые документы и файлы с префиксом IPO_.
  • После устранения причины восстановить хост из доверенного образа либо выполнить очистку по процедуре реагирования. Включить PowerShell Script Block Logging и Module Logging, Sysmon Process Create и Network Connect, централизованный сбор журналов и синхронизацию времени. Ограничить запуск неподписанных скриптов и исходящие соединения по утверждённым политикам.
